Man-in-the-Middle

Using Bettercap to sit between a target and the router on a shared network, so their traffic routes through the attacker's machine and can be inspected.

01What it is

A man-in-the-middle (MITM) attack positions the attacker's machine on the network path between two devices — typically a client and the router — without either side noticing. Once traffic is flowing through the attacker, it can be observed, logged, or altered before it reaches its real destination.

02How it works

On a local network, Bettercap achieves this with ARP spoofing: it sends forged ARP replies telling the target that the attacker's MAC address belongs to the router, and telling the router the same thing about the target. Both sides update their ARP tables and start sending traffic to the attacker, who forwards it onward so the connection still works while quietly passing through the middle.

  • Identify the target and the router on the local network
  • Spoof ARP replies so both sides route through the attacker
  • Enable IP forwarding so traffic keeps flowing transparently
  • Sniff or log the traffic passing through
  • Stop spoofing to restore normal ARP tables
1 · launch bettercap 
sudo bettercap -iface eth0
2 · scan the network 
net.probe on
net.show
3 · set the target 
set arp.spoof.targets 192.168.1.50
4 · start arp spoofing 
set arp.spoof.fullduplex true
arp.spoof on
5 · sniff traffic 
set net.sniff.output mitm.pcap
net.sniff on
6 · stop and restore 
arp.spoof off
net.sniff off
Note

Modern traffic is mostly encrypted with TLS, so sitting in the middle doesn't hand over plaintext credentials by itself. Attackers usually pair this with an HTTPS stripping or certificate substitution attempt, both of which are visible to an alert user or a properly configured browser.

03Detection & defense

ARP spoofing relies on the network's trust of unauthenticated ARP replies, so it leaves a distinct trail: rapid, repeated ARP announcements mapping the router's IP to an unfamiliar MAC address. This is easy to catch with static ARP entries or dedicated monitoring, and doesn't require inspecting the traffic content itself.

  • Use static ARP entries for critical hosts like the gateway
  • Enable dynamic ARP inspection (DAI) on managed switches
  • Watch for HTTPS certificate warnings — they're the clearest sign of interception
  • Prefer networks with client isolation, which blocks device-to-device ARP traffic entirely
